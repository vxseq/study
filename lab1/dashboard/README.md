# Дашборд проектов внедрения

Небольшой учебный сайт для учёта проектов и задач. Написан на **Python (FastAPI)**, **SQLite**, **HTML**, **CSS** и обычном **JavaScript**.

В нём можно создавать проекты, добавлять участников команды и задачи, назначать исполнителя, менять сроки и статусы. Статус проекта рассчитывается по его задачам:

- 🟢 **В сроке** — нет блокеров и незавершённых просроченных задач.
- 🟡 **Есть риски** — есть хотя бы одна незавершённая просроченная задача.
- 🔴 **Блокер** — хотя бы одна задача имеет статус «Блокер». Этот статус важнее просрочки.

## Запуск на компьютере (macOS, Windows, Linux)

Нужен Python **3.11 или новее**. Команды выполняются в папке `dashboard`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python migrate.py
python -m uvicorn main:app --reload
```

На Windows вместо `source .venv/bin/activate` используйте `.venv\Scripts\activate`, а вместо `python3` можно использовать `python`.

Откройте **http://127.0.0.1:8000/** — это сам сайт. Документация API: **http://127.0.0.1:8000/docs**.

При первом запуске проектов нет. Чтобы увидеть готовые примеры с тремя статусами, остановите сервер (`Ctrl+C`) и выполните:

```bash
python seed.py
python -m uvicorn main:app --reload
```

Демонстрационные записи добавляются **только если проектов ещё нет**. Данные хранятся в локальном файле `dashboard.db`, который не входит в ZIP. Удалять файл для обычного запуска не нужно.

## Запуск через Docker

Если установлен Docker Desktop, в папке `dashboard` выполните:

```bash
docker compose up --build
```

Откройте http://127.0.0.1:8000/. База хранится в отдельном Docker-томе `dashboard_data`, поэтому после перезапуска контейнера записи сохраняются. Локальная база `dashboard.db` и база в Docker — **разные**.

## Автоматические тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
black .
ruff check .
```

Тесты используют **отдельную базу в памяти**, поэтому не трогают пользовательские проекты. `black` автоматически форматирует код, `ruff` ищет распространённые ошибки и неиспользуемые переменные.

## Как сайт взаимодействует с backend

1. Пользователь нажимает «Добавить задачу».
2. JavaScript из `static/app.js` отправляет HTTP-запрос `POST /api/tasks/`.
3. FastAPI вызывает функцию в `routers/tasks.py`.
4. SQLAlchemy сохраняет задачу в SQLite.
5. Функция `services.py` обновляет статус проекта.
6. Сайт загружает список задач и проектов и показывает результат.

Статусы также перепроверяются при получении списка проектов. Поэтому проект станет жёлтым после наступления срока, даже если никто не менял задачу.

## Основные API

- `GET/POST /api/projects/` — список и создание проектов.
- `GET/PUT/DELETE /api/projects/{id}` — просмотр, изменение, удаление проекта.
- `GET /api/projects/{id}/status` — актуальный статус проекта.
- `GET/POST /api/tasks/` — список (можно `?project_id=1`) и создание задач.
- `GET/PUT/DELETE /api/tasks/{id}` — просмотр, изменение и удаление задачи.
- `GET/POST /api/users/` — список участников и добавление нового.
- `GET /api/health` — проверка работы сервера.

Полный интерактивный список доступен в Swagger по `/docs`.

## GitHub Actions

Если репозиторий GitHub содержит этот проект в `lab1/backend/dashboard`, скопируйте файл CI **в корень репозитория**:

```bash
mkdir -p .github/workflows
cp lab1/backend/dashboard/.github/workflows/tests.yml .github/workflows/dashboard-tests.yml
```

Команды выполняйте **из корня репозитория**, а не из папки `dashboard`. GitHub Actions читает workflow-файлы только из `.github/workflows` **корня репозитория**. После push можно увидеть проверки на вкладке Actions.
